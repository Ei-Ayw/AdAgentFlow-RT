\section{Experiments}
\label{sec:experiments}

We evaluate four runtime strategies (vanilla tool calling, retry-only, schema-only, \system) on three public benchmark task families (\mbox{$\tau^3$}-bench \textit{airline / retail / telecom} and AgentChangeBench \textit{airline / retail}) under controlled concurrency, repeated trials, and injected faults. Every experiment writes a machine-readable JSONL row keyed by task, run, method, ablation, adapter mode, and concurrency.

\textbf{Real benchmark data, real LLM.} The main matrix uses public \mbox{$\tau^3$}-bench and AgentChangeBench task fixtures cloned at their upstream GitHub SHAs. The runtime adapters drive a live Qwen3-8B endpoint served by vLLM~0.23.0 with constrained GPU memory so the harness can co-tenant on the shared GPU. Every run is recorded in external adapter mode; the customer goal, domain policy, and tool inventory are passed into the prompt, and public natural-language assertions drive fixture-backed scoring. This is not yet a full benchmark-native simulator execution, so we use the results as a production-stress harness study rather than a new benchmark leaderboard.

\subsection{Main Matrix}

The main setting sweeps all four methods across the full task set:
\begin{itemize}
    \item \textbf{Domains}: \mbox{$\tau^3$}-bench \textit{airline} (50 tasks), \textit{retail} (114), \textit{telecom} (2{,}285); AgentChangeBench \textit{airline}, \textit{retail} (50 tasks each).
    \item \textbf{Concurrency}: 1, 5.
    \item \textbf{Fault rates}: 0, 0.1, 0.2.
    \item \textbf{Stressors}: tool timeout, partial response, schema drift, stale context, duplicate message.
    \item \textbf{Tasks per cell}: 6, \textbf{trials}: 2.
\end{itemize}
The full matrix produces 1{,}392 JSONL rows across 39 runs (84 \mbox{$\tau^3$}-bench summary rows + 32 AgentChangeBench summary rows = 116 total) in approximately four hours on a single Qwen3-8B endpoint.

\subsection{Main Results}

Table~\ref{tab:main} reports the per-method averages over the full \mbox{$\tau^3$}-bench main matrix, weighted by the number of tasks per cell. Vanilla tool calling produces no compliant completions against the live LLM and is therefore dead-lettered for every run. Schema-only validation has the highest raw task success in this matrix, narrowly ahead of the full runtime. The full runtime's distinctive result is different: it is the only configuration with non-zero bounded recovery, and it reduces cost per successful task relative to retry-only while making violations explicit in the trace.

\subsection{AgentChangeBench Diagnostic Supplement}

The AgentChangeBench supplement measures target-change recovery rate (TCRR) and goal-shift recovery time (GSRT) under the same stressors. In this artifact, all AgentChangeBench task-success rates are zero and dead-letter rates are one, so the result is diagnostic rather than a main success claim. \system{} achieves the lowest measured GSRT (2.0 actions per goal shift vs.\ 7.1 for vanilla), but the absence of successful goal-change completions means this figure should be treated as evidence about bounded action count, not task-level recovery.

\subsection{Ablation Study}

The minimum ablation set disables one \system{} component at a time. Removing the contract monitor collapses recovery success to zero because the localizer and recovery controller have no explicit violation event to act on; removing the fault localizer inflates cost without improving success. The full method is the only configuration with non-zero bounded recovery in the ablation matrix, while zero silent failure is shared across methods in the current scoring setup.

\subsection{Reproduction and Audit}

The full experiment can be re-run end-to-end on the GPU server by following the runbook. Once the GPU output directory has been copied locally, the paper-facing artifacts are regenerated with:

\begin{verbatim}
./scripts/finalize_submission.sh --local-only
\end{verbatim}

For a fresh GPU run, execute the wait script followed by the finalization script. The audit gate fails fast if matrix coverage, methods, or benchmarks are missing. Replacing the vLLM endpoint with the public OpenAI API only changes the model endpoint environment variable; the rest of the harness stays the same.
