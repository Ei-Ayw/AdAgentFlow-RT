# ADR-0003：Repair 作为独立节点

- 状态：已采纳
- 日期：2026-07-14

## 背景

结构错误既可以在原 Agent 内无限重试，也可以进入独立修复节点。直接覆盖原输出会丢失失败证据，并让下游继续引用旧数据。

## 决策

Repair 使用独立节点和执行记录。修复输出必须通过目标节点 Schema；成功后写回目标节点当前快照，保留原 execution，清空依赖该结果的下游节点并从下一节点继续。失败受统一重试上限约束，最终进入人工审核或死信。

## 代价

- 编排分支和历史查询更复杂；
- 修复会增加 Token、延迟和成本；
- 必须维护目标节点到下游节点的依赖关系。

## 重新评估条件

当 DAG 不再是近似线性流程时，应把下游失效规则改为显式依赖图，而不是依赖步骤顺序。
